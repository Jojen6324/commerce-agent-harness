# Agent 任务执行优化与验证

本次在现有Agent Harness上补齐操作协议、结果检查和错误记录。按慢云环境需求增加RAG时间；没有据此认定超时根因已经查明。未修改任务语料、source_id、开发/保留划分或语义评测规则。

## 实现

- 写工具描述明确“当前调用只生成持久提案，不写业务”。参数齐全时生成`pending_action`；补业务信息与操作批准分开。确认仍执行保存参数，保持身份校验、事务和幂等重放。
- 只承诺查询/申请/转人工、声称生成提案而无提案、或只有省略号的答复，最多纠正一次；持续未完成则返回`validation_failed`。检查针对助手的结果声明，不按用户intent派发工具，不固定工具顺序或要求子Agent。
- 新提案的退款/退货原因必须可追溯到用户原话，拦截常见占位原因；只从服务端提供的用户轮次取证，不从助手摘要取证。该检查约束出处，不独立证明用户描述真实或政策资格成立。
- 商品搜索支持空格、斜线等分隔关键词的同时匹配，保留完整原词优先和LIKE字面转义；未定位商品时不得把空结果说成库存0。
- RAG工具默认180秒，整轮默认300秒，普通业务工具保持30秒。共享剩余deadline，Token/模型次数/工具次数限额不变。配置见`.env.example`。
- API保留`status`、`error_code`、`diagnostics.failure`、`events`与运行ID；限流、预算耗尽、校验不可用不再伪装完成。生成降级保留原因，资料摘录只引用一个完整来源；不再把校验器不可用说成未配置模型。

## 可核对的结果

- 最后4会话、8轮实际API调用，确定性门槛全部通过：`agent_032_refund`与`agent_043_foreign_confirm`完整通过；`agent_070`、`agent_095_missing_reason`保留语义待审。
- `agent_032_refund`先补问，原因补齐后产生真实退款提案；确认前无业务变化。确认后订单变为`refunding`，只新增一笔3900分的`requested`退款和审计记录，未声称已到账。
- `agent_043_foreign_confirm`先保存取消提案，另一用户确认返回HTTP400，原提案保持pending，业务状态未变。
- `agent_095_missing_reason`首轮没有创建提案；用户提供具体原因后仅生成提案，没有执行业务写入。
- `agent_070`实际调用入队能力取得human队列与工单号，不以口头承诺算完成；这是本地演示队列，非外部真人已接通。
- 11会话轮的`agent_024_cancel`整体仍是error（首轮AGNES429），但后续提案、确认、重复确认三个轮次通过，数据库证明取消只执行一次。不得把该会话整体改判通过。商品材质查询已查得SKU-TEE和纯棉描述，仍保留语义审阅。
