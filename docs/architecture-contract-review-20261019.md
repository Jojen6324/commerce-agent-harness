# 历次修复与架构契约复核

结论：确实出现了局部补丁累积，主要集中在完成度判定、补问答复和引用传递。持久化审批、身份隔离、幂等确认、人工服务数据库和分层超时等修复属于基础能力完善，不能一概视为补丁。此次直接调整已确认的契约缺陷，没有增加按任务 ID 触发的执行分支。

| 位置 | 发现的问题 | 本次调整 |
|---|---|---|
| 完成度判定 | `ask_user` 已明确给出缺失信息，运行器仍解析问题文案中的操作承诺，误判条件句 | 结构化缺项单独处理；自由文本完成检查只应用于自由文本终答。索要操作批准仍单独拒绝，确认继续由持久提案处理 |
| 补问答复 | 从整段 messages 倒找答案，可能重新带回历史答复或已被拒绝的候选 | `ask_user` 新增显式部分答案字段；只组合当前调用的答案和问题，不扫描历史 |
| 答案校验 | `needs_input` 一律跳过校验，即使包含政策结论；修正后又可能丢失补问状态 | 有实际工具证据的补问答复进入同一忠实性校验；纯缺项问题不增加模型调用；成功改写保留原状态 |
| 修复预算 | 同一错误原样重复时仍再次修复，扩大调用消耗 | 同一问题签名只修一次；最多允许两个不同的问题修复，仍受全局步数与时间限制 |
| 政策证据 | 只看工具名和 success，空搜索也算有证据；专家返回的真实来源反而可能不被认可 | 检查实际片段或结构化结果；专家结果须有实际来源片段，不要求固定工具顺序或专家调用 |
| 引用 | API 把全部检索片段列为引用；自我修正后还可能携带旧答案引用 | API 只列终答明确引用或原样复用已校验答案的来源；修正时重新绑定来源，拒绝未知的声明来源 |
| 提示词 | 不断加入某个失败案例的天数、运费、退款时效，政策事实分散到多个全局提示词 | 抽出生成、校验、修正共用的证据规则；具体期限和责任从知识文档读取 |

原有审批与持久化约束继续有效：没有真实业务工具结果就没有持久提案；确认时核对用户、会话、保存参数和幂等状态；人工工单回执由服务端按实际状态生成。相关回归包含这些约束，未放宽权限或写入验收。

评测中的笑话/闲聊移除机械关键词、跨轮查询复用同会话工具结果，是合理的验收校正；它们不能代替政策适用范围和引用支持关系的审阅。`answer_any` 等词面检查仍只是确定性信号。

本轮新增/执行的回归覆盖历史和被拒答案不复活、当前部分答案随补问交付、补问中的政策答复仍校验、修正保留补问状态、空检索不算证据、专家证据可用、终答仅列实际引用及改写后引用更新。75 项相关测试通过，Ruff 与 `git diff --check` 通过。本轮没有重新调用 AGNES 或 DeepSeek，不能据此宣称新代码的模型任务成功率。

复核也更正了旧语义标签：`agent_090` 用户未说明品类，答复却说“质量问题须在签收后15日内提交视频凭证”。通用政策仅要求“凭证”，视频要求来自数码专用政策；原语义通过判定过于宽松。当前这批 12 条历史响应为确定性 12 通过、语义 11 通过 / 1 失败；开发集逐任务历史清单更正为 94 通过 / 1 失败。原始响应与初次标签保留，[结构化复核记录](architecture-contract-review-20261019.json) 记录更正及响应散列。

剩余边界：自由文本承诺检查和政策问题识别仍含启发式规则；它们不承担真实写入授权，也不能证明完整语义正确。引用收敛能证明实际来源，是否支持全部结论仍需语义审阅。当前历史清单跨多个版本和模型，新架构尚未做同版本全量真实模型评测，不能称为全部问题已经解决。
