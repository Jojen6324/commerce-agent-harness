# AGNES 小样本调试（2026-10-20）

分支：`refactor/business-agent-evo-runtime`。模型 `agnes-3.0-flash`，通过现有 AGNES 配置连接；使用隔离 SQLite 与已有 fixture，无生产业务写入。

## 范围与配置

这是运行链路调试，不是完整评测，也不是 A/B 优劣证明。四个固定开发任务与诊断会话分开记录，诊断均派生自已有 `collab_003` fixture。

配置：上下文 32000、请求累计 128000 Token、32 模型调用、14 工具调用、3 委派、Main 12 步；保护 Main 的额度为 32000 Token / 8 模型 / 6 工具；请求 360 秒、工具 30 秒、知识 180 秒、模型 30 秒、最多 3 次模型尝试。Critic 关闭。

## 发现与修复

1. **咨询误提案**：模型误调用申请工具时，仅禁止“明确说不要操作”不足以覆盖普通咨询。新增服务端 case 授权标志，由统一执行器拦截未经请求的提案；原任务已请求办理时，后续补充原因可延续授权。确认、归属、身份校验保持原有路径。
2. **补问丢失任务**：模型以普通最终文本补问，状态却 completed，下一轮产生新 case。现有有界完成检查要求改用 ask_user，保留 missing_fields；未提高步数或引入新循环。
3. **委派后重复查证**：工具返回专家结果后追加已有证据复用指引，增加事实完整性标志；不强制依赖专家摘要。其降低重复调用的稳定性尚需更多同题验证。
4. **观察时间**：用实际工具完成时间保存实时证据时间戳，避免在结束响应时重新计算新鲜度。
5. **内部调度边界**：调试中曾尝试让 Main 遵循用户指定专家，该改动已按用户要求撤销。最终策略不允许用户指定内部 Agent 或覆盖路由，婉拒调度指令后继续处理实际业务需求。诊断入口改用自然业务问题，是否委派只作观测指标，不作为成功标准。

新增/适配测试覆盖咨询无提案、普通文本补问的有界修复与同 case 续办；原有 evaluator mock 改用生产 ask_user 协议，未修改数据集、预期答案或评分。

修复后“帮我退货，订单 ORD10002 → 杯子有裂纹 → 确认 → 再确认”六项检查全部通过：先 needs_input、同 case、真实待确认方案、仅一条退货记录、相同确认回执、不宣称退款到账。

修复前/后这一次诊断会话各自累计报告 24066 / 16023 Token，工具调用均为 3。它们不是受控重复实验，不能据此宣称总体节省比例。

原始售后诊断实际调用 AfterSales，专家独立查询商品、物流与政策，无 Order/Policy 依赖，无提案和副作用；另一次未委派。`specialist_final.json` 六项检查通过，但使用了随后撤销的“遵循用户指定专家”提示词，只保留为历史调试记录，不能代表最终路由策略。最终策略的自然业务问题委派行为尚未重新进行真实模型验证。
