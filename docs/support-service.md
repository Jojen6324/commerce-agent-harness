# 最小人工工单服务与工程修复

`escalate_to_human` 现在将工单真实写入 `support_tickets`，不再拼接临时票据。它是供工作人员轮询受理的数据库待办服务，不是实时人工聊天、外部呼叫中心或自动退款服务。

## 客户侧

- Agent 调用保存工单，身份和会话来自后端 `ToolContext`。同用户、同会话、同原因重复提交返回原工单。
- 保存成功后由服务端生成确定性回执，说明真实编号、当前状态、尚未接通及不保证处理时间。写订单/退款仍使用原有持久化 Action 和确认流程。
- `get_support_ticket` 可读取当前用户当前会话的工单状态和工作人员填写的处理答复；其他用户或其他会话均不可读取。
- 重新提出不同问题可以建立另一张工单；重复提交已经解决的同一请求仍返回原记录，不自动重新打开。

## 工作人员侧

配置 `ADMIN_API_TOKEN` 并重启服务。以下接口在所有环境都要求请求头 `X-Admin-Token`；未配置令牌时关闭，开发环境也不放行。不要将令牌写入代码或对话。

| 接口 | 功能 |
|---|---|
| `GET /api/v1/admin/support-tickets?status=pending&limit=50` | 待受理工单，支持 pending/in_progress/resolved，最多100条 |
| `GET /api/v1/admin/support-tickets/{ticket_id}` | 工单详情及最近50条会话消息 |
| `PATCH /api/v1/admin/support-tickets/{ticket_id}` | 原子接单或解决，并写审计日志 |

接单请求体：

```json
{"expected_status":"pending","status":"in_progress","operator_id":"staff-1"}
```

解决请求体：

```json
{"expected_status":"in_progress","status":"resolved","operator_id":"staff-1","resolution":"已核实问题，处理说明……"}
```

仅允许 `pending → in_progress → resolved`，解决时必须填写说明。条件更新防止重复接单和过期状态覆盖；处理中仅相同 `operator_id` 可解决。管理员持有同一个令牌，`operator_id` 是管理员声明的工作人员标识，尚非独立坐席登录/RBAC。工单解决不修改订单、退款或退货状态。

这是API待办服务，需要工作人员实际查看和受理；尚未提供坐席网页、自动通知、外部客服接入、经理专属路由或响应时限保证。聊天身份仍沿用项目原有用户/会话模型，生产使用须接入真实用户认证。

## 数据库升级

新增迁移 `0004_support_tickets`，在已配置正确数据库连接的 Alembic 环境执行 `alembic upgrade head`。本地 SQLite 开发启动仍通过 `init_schema` 增加缺少的表，不删除现有记录。迁移连接由 `alembic.ini` 决定，不能假定自动读取应用的 `DATABASE_URL`。

## 已修复的工程问题

- 原始工具结果无有效引用时不再被压缩成 `artifact_ref=null`。Runner 对工具结果附真实、用户/会话隔离的存储引用，保留摘要和证据ID；读取引用后保护原文，避免再次外置形成循环。无效引用允许在原有预算内纠正，权限检查仍保留。
- 检索词可改写，但答案生成和校验绑定后端原始用户问题；直接复用RAG答案前核对 `answered_question`，避免丢掉“签收8天”等任务条件。
- 转人工成功回执由后端根据已保存工单生成，防止模型将“保存待受理”扩写成“真人将联系”。完成检查补充“接通人工”和“可以创建工单”等遗漏表达，不强制固定工具顺序。
- 商品中文复合词查无结果后使用已有分词做受约束的AND检索；空结果显式标为未匹配，详情明确技术规格未录入。
- 券工具同时返回当前索引中的优惠券和叠加政策原文，包含定制排除等限制，不再将券目录摘要冒充完整规则；领取入口和账户资格标为未知。
- 物流事件标明中文含义与时间来源，`warehouse/paid_at` 不等于出库；`city` 明确是订单收货城市，不是实时包裹定位。
- 文档中文标题、章节、来源和政策版本贯穿嵌入、BM25、精排、证据充分性判断、生成、纠错和忠实性检查。专用品类范围仍需模型判断，不能声称确定性杜绝语义泛化；充分性检查失败不再将“有片段”等同“足够”。

评测同时增加工单数据库快照和回执关联校验；仅原样本明确允许交接的结果路径可新增工单，其他任务新增工单记副作用失败。工单状态与订单/退款状态分开检查，原始数据、fixture和划分未改。

## 验证

新增集成验证覆盖持久化重开、幂等提交、未授权拒绝、条件接单、处理说明、状态审计、用户/会话隔离、空引用压缩、商品查询、完整券规则及物流字段契约。实际模型回归另行记录，不把模拟模型测试当作AGNES表现。
