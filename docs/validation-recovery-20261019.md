# 失败任务诊断与验证恢复

本次处理此前95会话开发集中的10条失败任务，另用3条已有派生多轮任务检查退货、退款和人工复核边界。重复执行开发集不构成新数据，没有运行保留集。用户指定：调试使用AGNES；相关任务通过自动验收和逐会话语义审阅后，才使用DeepSeek做最终回归。只本地提交，不推送。

## 通用原因与修复

- 大工具结果外置后，主Agent只收到通用“已保存”提示，实际政策正文不可见。现在传递有长度预算的证据摘要，保留完整段落、来源元数据、业务事实、真实artifact引用及完整性标志；省略的内容仍可通过工具读取。
- 原来的答案改写脱离工具循环，遇到缺证据只能继续猜。现在校验失败将具体反馈送回仍可调用工具的主循环，最多两次修复，并受共享步数、调用数和时间预算约束。拒绝的草稿不作为已发送消息进入用户会话。
- 校验器混淆业务政策、应用能力和实际执行。现在显式提供完整工具能力契约，同时将实际工具结果作为独立证据；可生成待确认申请不代表已经批准或执行，不允许将模型生成草稿作为独立证据。
- 校验与改写保留完整证据及逐次结构化审计，验证引用属于当前可用来源，区分语义拒绝与接口/格式错误。保留真实业务写入的确认边界。
- 同为15天的举证窗口、数码超期处理和维修备件等待时间容易混淆。提交ea32c0e澄清三个知识文件的适用范围与起算事件，未更改天数和业务条件，同时更新固定知识文件哈希。因此这一阶段的评测语料摘要已改变，不能将结果变化全部归因于代码。

没有按任务ID路由，没有强制工具顺序或子Agent调用，没有放宽验收规则。修复保留可审计的失败结果，不将校验拒绝自动转成业务成功。
